# 学習プロトコル（体験版 Session 00〜03 の進め方）

> **このページは AI の進行台本です。進行役は AI で、学習者が毎回このページを探して開く必要はありません。**
> セットアップ後は、AI に「**始めます。あなたがリードしてください**」または「**続きから始めよう**」と送るだけで大丈夫です。

この体験版は、本編の入口となる Session 00〜03 をそのまま学びます。所要時間の目安は 1 回 45〜90 分です。

---

## まず知っておくこと

ブラウザで見られる `apps/trial-web/` は、講座の雰囲気を知るためのデモです。**Session 00〜03 の演習ではありません。** この4回で学ぶのは、これから Web を作るための「学び方」と「共通の道具」です。

自分で HTML のページを作り、ブラウザで見た目の変化を確かめるのは本編 Session 06 からです。したがって、体験版の学習中に `npm install`、`npm run dev`、Next.js、`.tsx` の編集は行いません。

AI が使う資料は次のとおりです。

| 役割 | パス |
| --- | --- |
| 4回の現在地 | `docs/roadmap-trial.md` |
| 技術全体での位置 | `docs/tech-map.md` |
| Session 00 の教材 | `knowledge/lessons/session-00-project-guide.md` |
| Session 01 の教材 | `knowledge/lessons/session-01-terminal-and-files.md` |
| Session 02 の教材 | `knowledge/lessons/session-02-git-basics.md` |
| Session 03 の教材 | `knowledge/lessons/session-03-github-basics.md` |
| 用語の正本 | `knowledge/glossary.md` |
| 学習記録 | `knowledge/sessions/` |
| 学習者カルテ | `knowledge/profile.md` |

## AI が最初にすること

学習者が「始めます」「続きから」などと送ったら、AI は説明の前に次を行います。

1. `knowledge/profile.md` を読む。初回で存在しない場合は、Session 00 の中で `knowledge/profile.example.md` を基に作る
2. `knowledge/sessions/` の最新記録を読む
3. 初回なら Session 00、それ以外なら未完了の次の Session を決める
4. 前回の様子を1〜2文で振り返り、今日の流れを予告する
5. 今日の教材ファイルと、最初に開く節を正確に指定する

学習者にテーマ選びや文書探しをさせません。AI が「今日は Session 01 です。まず `knowledge/lessons/session-01-terminal-and-files.md` の『🎯 このセッションの到達目標』を開いてください」のように、次の1手を具体的に案内します。

## 毎回の 6 フェーズ

```
1. 予習   → 今日の教材の地図を見る
2. 計画   → 今日のゴールと、手を動かす場所を確認する
3. 理解   → 1概念ずつ、意味から分かる
4. 実践   → 自分の指で操作する
5. 検証   → 閉本再現と理解チェックで「見ないでできる」を確かめる
6. 記録   → AI が次回へ引き継げるよう、記録とカルテを更新する
```

### 1. 予習 — 今日の地図を見る（5〜10分）

AI が今日の教材を指定し、最初に以下を短く確認します。

- 何ができるようになるか
- 前回までに使うもの
- 今日の新しい言葉
- どこで手を動かすか

全部を理解してから進む必要はありません。「今日は何をする回か」が見えれば十分です。分からない用語が出たら、AI は英語の意味から説明します。

### 2. 計画 — 今日のゴールを決める（3分）

AI が、今日の到達点と終了条件を短く伝えます。たとえば Session 01 なら「`pwd`、`ls`、`cd` を意味から説明し、宝探しを自力で進められる」がゴールです。

学習者は「どのテーマにしよう」と決める必要はありません。途中で疲れた、時間が足りないなどがあれば、AI が記録を見て途中で区切る場所を提案します。

### 3. 理解 — 1概念1アクションで進める（15〜25分）

AI は教材の順番に沿い、概念を1つ説明するたびに 👀 **みてみて** または ✋ **やってみて** を1つ出します。

```
説明する → 30秒〜2分で観察・操作する → 結果を聞く → 次の概念へ
```

例:

- file（ファイル）= 英語で「書類」→ VS Code の一覧で `README.md` を見つける
- `pwd` = print working directory（今の作業場所を表示する）→ 自分のターミナルで1回実行する
- `git add` の add =「追加する」→ `git status` で記録候補に入った表示を読む

用語・略語・コマンド名は初出で英語の意味を説明します。できなかったときは先に進まず、答えの一括提示ではなく「次の1手」だけを出します。

教材の説明だけで足りないときだけ、`knowledge/prompts/02-material-generation.md` の補助説明プロンプトを使えます。これは**教材を新しく作らせるためのものではなく**、同じ概念を別の角度から理解するためのものです。

### 4. 実践 — 自分の指で操作する（20〜35分）

| Session | 実践すること | AI の役割 |
| --- | --- | --- |
| 00 | プロジェクトの地図を実物と照らし、カルテを作る | どの場所を見るかを指定し、学習者への質問を1つずつする |
| 01 | `practice/session-01-terminal/` でターミナルの宝探しをする | コマンドの意味を説明し、表示を一緒に読む |
| 02 | Git の状態確認・記録・履歴確認を行う | `status` / `add` / `commit` / `log` の意味を1つずつ確かめる |
| 03 | 自分のフォーク内でブランチ→push→PR→マージ→pullを一周する | GitHub の画面とターミナルの関係を確認しながら、次の1手だけ案内する |

学習者が入力・操作するのが原則です。AI は完成済みのコマンド列や答えを代行しません。

Git の流れも、先取りしません。

- Session 00〜01: ブランチや PR を必須にしない
- Session 02: まず手元で Git の記録を作る
- Session 03: 初めて自分のフォーク内で branch（枝）→ PR（変更を取り込んでほしいというお願い）→ merge（合流）を体験する

### 5. 検証 — 閉本再現を必ず行う（10〜20分） 📕

教材を見ながらできたことは、まだ「見ればできる」状態です。終了前に必ず、教材とコマンド履歴を閉じて再現します。

1. AI が、今日の課題と少しだけ違う仕様または質問を1つ出す
2. 学習者が何も見ずに説明・操作する
3. 詰まった場合、AI は答えを出さず「次の1手」だけを示す
4. できたら、学習者が「なぜこの操作をしたか」を自分の言葉で説明する

Session 00 は口頭での再現、Session 01〜03 は操作を含む再現にします。合格ラインは「動いた」だけではなく、**見ずにできて理由を説明できた**ことです。

閉本再現の後、AI は理解チェックを1問ずつ行います。簡単な定義は記述式にし、選択式にするのは次のような「考えないと答えられない」問題だけです。

- 操作またはコマンドを実行したときの結果
- 意図どおりに進まない箇所の発見
- 2つの操作の使い分け
- エラー文が示す原因
- 操作の順番

選択肢は、初学者が実際に迷う内容にします。「すべて正しい」のような当てずっぽうで避けられる選択肢は使いません。通常は AI が自ら実施します。必要なら [理解チェック用プロンプト](../knowledge/prompts/03-understanding-check.md) を使います。

### 6. 記録 — AI が次回に引き継ぐ（5分）

このフェーズは AI の必須作業です。学習者に「記録しておいてください」と頼まず、終了前に次の2つを更新します。

1. `knowledge/sessions/YYYY-MM-DD-session-XX-テーマ.md` の学習記録
2. `knowledge/profile.md` の学習者カルテ

学習記録には、少なくとも以下を残します。

- 今日のテーマ
- やったこと
- 学んだこと
- ⚠️ 詰まったところ
- 💪 スムーズだったところ
- 📕 閉本再現の結果
- 理解できていないこと
- 理解度チェック結果
- 次やること

「詰まったところ」は「Git が難しかった」ではなく、「`git add` の後に何が変わるかが結び付かず、表示を見比べるヒントが必要だった」のように具体的に書きます。

カルテには、得意そうなこと、つまずきやすい傾向、効果があった教え方、ペース、次回の指導方針を前向きな表現で追加します。書き終えたら、AI は「今日の記録を保存しました。次は〜から始めます」と報告します。

記録を取りこぼした場合だけ、[学習まとめ用プロンプト](../knowledge/prompts/04-learning-summary.md) を使います。

## Session 終了チェック

- [ ] 今日の教材にある 👀 / ✋ を、結果を確認しながら進めた
- [ ] 自分の手で操作した
- [ ] 教材を閉じた状態で、少し変えた課題を再現した
- [ ] なぜその操作をしたかを自分の言葉で説明した
- [ ] 理解チェックで、怪しいところを見つけた
- [ ] `knowledge/sessions/` に学習記録が保存された
- [ ] `knowledge/profile.md` が更新された

Session 03 では、これに加えて、自分のフォーク内の PR を確認してからマージし、手元の `main` に取り込むところまでを完了条件にします。

---

## 困ったとき

学習者は「詰まった」「画面が違う」「エラーが出た」と、そのまま AI に伝えれば大丈夫です。AI は次を行います。

1. 表示・操作・エラーメッセージをそのまま確認する
2. エラーメッセージを英語の意味から説明する
3. 一度に直し方を並べず、次の1手だけを試す
4. 設定に問題がありそうな場合だけ、該当するセットアップ箇所を具体的に示す
