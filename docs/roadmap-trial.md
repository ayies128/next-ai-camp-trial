# 体験版ロードマップ — 本編へつながる Session 00〜03

> この体験版は「雰囲気だけを触る4回」ではなく、全 24 セッションの本編の**最初の4回そのもの**です。
> セットアップが済んだら、AI に「**始めます。あなたがリードしてください**」と送るだけで始まります。次の教材を探したり、テーマを選んだりする必要はありません。

このページは、全体像を一度確認したいときの地図です。ふだんの進行は AI が [学習プロトコル](./learning-protocol.md) に沿って行います。

---

## どこを歩く4回なのか

Web サービスは、見える画面を作る **フロントエンド**（front = 前 / end = 側）、見えない場所でデータを扱う **バックエンド**（back = 後ろ）、世界へ届ける土台の **インフラ**（infrastructure = 基盤）でできています。

そのどこでも使う道具が、ターミナル・Git・GitHub・AI です。体験版ではまず、この **⓪ 共通の道具** を4回で身につけます。

```text
体験版 / 本編の入口

Session 00  プロジェクトの歩き方
Session 01  ターミナルとファイルの世界
Session 02  Git ってなに？
Session 03  GitHub を使ってみよう
          ↓
本編 Session 04〜24
インフラ → フロントエンド → バックエンド → 公開 を1周する
```

より大きな地図は [技術地図](./tech-map.md) にあります。**full stack**（full = 全部の / stack = 積み重ね）とは、この3つの技術層をつないで扱うことです。この講座では、深掘りする前にまず全体を1周します。

---

## ブラウザのデモと、学習の本編は別です

このリポジトリにはブラウザで「動くもの」を見られるデモがあります。これは、完成したアプリの雰囲気を先に見て「この先に何を作れるのか」をつかむための展示です。

一方、Session 00〜03 は、そのアプリを作る前の土台です。ここでターミナル・ファイル・Git・GitHubを使えるようにしてから、本編で Web の仕組み、HTML、CSS、JavaScript を順に学びます。

そのため、この体験版の学習では Next.js、`.tsx`、`npm install`、`npm run dev` を使いません。見た目を自分で変えてブラウザで確かめる最初の学習は、本編 Session 06 です。

## 4つのセッション

AI は毎回、教材の節を指定して、**1つ説明したら1つ観察・操作する**リズムで進めます。読み終えることではなく、見ないで説明・操作できることがゴールです。

### Session 00: プロジェクトの歩き方

**テーマ**: この教材の地図と、AI と一緒に学ぶ方法をつかむ

| 項目 | 内容 |
| --- | --- |
| 教材 | `knowledge/lessons/session-00-project-guide.md` |
| すること | プロジェクトのフォルダ地図を実物と見比べる。学習記録と学習者カルテの役割を知る。AI と役割分担を決める |
| 英語から知る言葉 | project（計画・企画）、lesson（授業）、profile（人物紹介） |
| できるようになること | 「教材はどこ」「記録はどこ」「次はどう始めるか」を自分の言葉で説明できる |
| 終わりの証拠 | `knowledge/profile.md` が作られ、6フェーズと閉本再現の意味を見ずに説明できる |

この回の合言葉は、**「考えて答えるのは自分、進行と記録を整えるのは AI」**です。

### Session 01: ターミナルとファイルの世界

**テーマ**: パソコンの中を、文字の命令で探検する

| 項目 | 内容 |
| --- | --- |
| 教材 | `knowledge/lessons/session-01-terminal-and-files.md` |
| 練習場所 | `practice/session-01-terminal/` |
| すること | ファイル・フォルダ・パスを知り、`pwd` / `ls` / `cd` / `mkdir` を自分で打つ。ターミナルの宝探しをする |
| 英語から知る言葉 | file（書類）、folder（書類ばさみ）、path（道筋）、directory（案内簿） |
| できるようになること | 今いる場所を確かめ、ファイルの場所を文字でたどれる |
| 終わりの証拠 | 教材を閉じても、目的地へ移動する順番と理由を説明できる |

ターミナルは怖い黒い画面ではなく、どの技術層にも指示を出せる「操縦席」です。

### Session 02: Git ってなに？

**テーマ**: ファイルの変更に、安全なセーブポイントを作る

| 項目 | 内容 |
| --- | --- |
| 教材 | `knowledge/lessons/session-02-git-basics.md` |
| すること | ファイルを変え、状態を確かめ、記録候補に入れ、記録し、履歴を見る |
| 英語から知る言葉 | status（状態）、add（追加する）、commit（確定する・委ねる）、log（記録簿） |
| できるようになること | `git status` / `git add` / `git commit` / `git log` を、何のための順番か説明できる |
| 終わりの証拠 | 教材を閉じても、小さな変更を自分で記録し、どの時点で何が起きたか言える |

Git はクラウドサービスではありません。まず手元の変更履歴を守る道具です。GitHub へ送るのは次の Session 03 で学びます。

### Session 03: GitHub を使ってみよう

**テーマ**: 手元の記録を、ネット上の自分の場所と行き来させる

| 項目 | 内容 |
| --- | --- |
| 教材 | `knowledge/lessons/session-03-github-basics.md` |
| すること | 自分のフォークを確認し、ブランチを作り、変更を push して PR を作り、自分でレビューしてマージする |
| 英語から知る言葉 | push（押し出す）、pull（引っ張る）、branch（枝）、merge（合流する）、request（お願い） |
| できるようになること | Git と GitHub の違い、origin と upstream の行き先、PR が必要な理由を説明できる |
| 終わりの証拠 | 自分のフォーク内で branch → push → PR → merge → pull を、見ないで一周できる |

PR は **pull request**（変更を取り込んでください、というお願い）の略です。仕事の開発現場でも、変更を本体へ入れる前にこの流れで確認します。

## 毎回、ここまでできたら完了

1. AI の指定した教材を、1概念1アクションで進めた
2. 自分の指で操作した（AI に丸ごと代行させない）
3. 教材と操作履歴を閉じて、少し変えた課題を再現した
4. なぜその操作をしたかを自分の言葉で説明した
5. AI が `knowledge/sessions/` の記録と `knowledge/profile.md` のカルテを更新した

詰まることは失敗ではありません。**詰まった場所が分かること**が、閉本再現をする目的です。AI はその記録を読んで、次回はそこから始めます。
