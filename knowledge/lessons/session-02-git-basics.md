## 🗣 今日の新出用語

| 用語 | 英語の意味 | 一言でいうと |
| --- | --- | --- |
| Git（ギット） | 道具の固有名詞 | ファイルの変更履歴を記録する道具 |
| version（バージョン） | 版・改訂版 | ある時点の状態 |
| `status` | 状態 | 今の変更状況を見る |
| `add` | 追加する | 次の記録に入れる変更を選ぶ |
| stage（ステージ） | 舞台・準備段階 | 記録候補を置く場所 |
| `commit` | 確定する・約束する | 変更を履歴として確定する |
| `log` | 記録・日誌 | 確定済みの履歴を見る |
| `diff` | difference（違い）の略 | 変更前後の差を見る |

→ 詳しくは [用語辞典](../glossary.md) を見てください。

## 📖 理論パート — 読みながら小さく確かめる

### 1. Git がないと、前の状態と変えた理由が消える

ファイルを上書き保存すると、前の内容は見えなくなります。コピーを増やせば残せますが、どれが最新か、何を変えたのかが分からなくなります。

**Git** は、同じファイルをコピーだらけにせず、節目ごとの状態を **version（バージョン）= 版・改訂版** として記録する道具です。ゲームのセーブポイントに似ていますが、何をどう変えたかも後から確認できます。

> 👀 **みてみて**: 教材フォルダのいちばん上でターミナルを開き、次を打ってください。

```bash
git log -1
```

`-1` は「最新の 1 件だけ」という追加指定です。最新の記録が 1 件だけ表示されます。これが、あなたがまだ変更していない教材にもすでに履歴がある証拠です。表示から抜けられないときは `q` を 1 回押します。

### 2. `git status` は、作業を始める前の健康診断

**status = 英語で「状態」**です。`git status` は「いま何が変わっていて、次に何を記録する予定か」を見せます。作業を始める前と終える前に必ず確認する癖をつけます。

> ✋ **やってみて**: 教材フォルダのいちばん上で次を打ってください。

```bash
git status
```

最初は `nothing to commit, working tree clean` のような表示が理想です。意味は「記録する変更はなく、作業場所はきれい」です。もし自分で触った覚えのない変更が見えたら、勝手に消さず、AI に画面を見せて理由を確認してください。

### 3. `add` は選ぶ、`commit` は確定する

Git はいきなり全部を記録しません。まず **`add` = 追加する** で、「次の記録に入れる変更」を選びます。この選択用の場所を **stage（ステージ）= 舞台・準備段階** と呼びます。

次に **`commit` = 確定する** で、選んだ変更を履歴として確定します。2 段階なので、関係ない変更を混ぜずに記録できます。

> ✋ **やってみて**: VS Code のファイル一覧で `practice/session-01-terminal/my-git-note.md` を新規作成し、次を**自分の言葉で**書いて保存してください。

```markdown
# Git 練習メモ

今日わかったこと: Git は変更の履歴を残す道具。
```

保存したら、教材フォルダのいちばん上で次を 1 行ずつ実行します。

```bash
git status
git add practice/session-01-terminal/my-git-note.md
git status
```

最初は「まだ記録されていないファイル」、最後は「次の記録に入る変更」と表示が変わります。自分で変化を読んでみてください。

### 4. `commit` で履歴になり、`log` と `diff` で確かめられる

**`log` = 記録・日誌**なので、確定済みの記録を一覧します。**`diff` = difference（違い）の略**なので、まだ確定していない変更の前後を見比べます。

`commit` の `-m` は **message（メッセージ）= 伝える文章**の略です。「なぜこの記録を作ったのか」を短く残します。

> ✋ **やってみて**: さっき選んだメモを、次のように確定してください。

```bash
git commit -m "docs: add my Git practice note"
git log -1
```

次に `my-git-note.md` の末尾へ、今日気になったことを 1 行追加して保存します。保存後、次を打って前後の差を見てください。

```bash
git diff
```

`+` が付いた行が、あなたが増やした内容です。

## 🎨 演習課題（15 分）

### 課題 1: 2 回目のセーブポイントを作る

さっき `my-git-note.md` に追加した 1 行を、2 回目の履歴にします。教材を見ずに、次の順番を思い出して実行してください。

1. 今の状態を見る
2. このファイルだけを次の記録に選ぶ
3. 違いを確認する
4. 「Git 練習メモを更新した」と分かるメッセージで確定する
5. 最新 1 件の履歴を見る

確認するときのコマンドは、次の通りです。`git add` の**後**の差を見るので、3 行目は `--staged` を付けます。staged は stage（記録候補を置く準備場所）に入った変更だけを見る指定です。

```bash
git status
git add practice/session-01-terminal/my-git-note.md
git diff --staged
git commit -m "docs: update my Git practice note"
git log -1
```

ヒントが必要なら、コマンド名ではなく「選ぶ段階と確定する段階のどちらで止まったか」を AI に伝えてください。

### 課題 2: 3 つの状態を言葉にする

`git status` を見ながら、次の 3 つを自分の言葉で説明してください。

| 状態 | 自分の言葉での説明 |
| --- | --- |
| まだ Git が記録対象にしていない変更 | |
| `git add` の後、次の記録を待っている変更 | |
| `git commit` の後、履歴になった変更 | |

説明したら AI に「間違いがある箇所だけ直して」と頼みます。

## 🆘 つまずき FAQ

### Q: commit 時に名前やメールアドレスを設定するよう言われた

A: Git の初期設定がまだです。[セットアップガイド](../../docs/setup.md) の Git の項目を開くか、AI にエラー全文を見せて「名前とメールアドレスの設定が必要と言われた。自分で確認しながら設定したい」と頼んでください。

### Q: `nothing to commit` と表示された

A: 記録できる変更がない状態です。`my-git-note.md` を保存したか、すでに同じ変更をコミットしていないかを `git status` と `git log -1` で確認します。

### Q: `git status` に知らないファイルが出た

A: そのファイルを追加も削除もせず、名前と表示を AI に見せてください。理由を確認してから次の操作を決めます。
